## 谢嘉鸿 · 架构与智能体内核

**《我以为多步调用是最简单的部分》**

分工时我觉得主循环最好写：不就是「调工具 → 拿结果 → 再调」吗？真正写起来才发现，最难的不是循环，是**判断多步到底是真的还是假的**。

我们最初的版本是这样的：规划器一次返回两个 `ToolCall`，主循环循环执行两次。看起来走了两步，但实际上第二步的参数在**规划的那一刻**就定死了——那时候第一步还没执行，数据根本不存在。演示时它确实画出了图，但画的是空图。这种"假多步"最可怕的地方是它**看起来是工作的**，只是结果不对。

改成真多步后，主循环变得很短：

```python
for step in range(max_steps):
    decision = planner.plan(ctx)      # 每次只做一个决定
    if decision.final_text is not None:
        return ...
    for call in decision.calls:       # 实际只有一个
        result = self._invoke(call)
        ctx.observations.append(result)
```

代价是我必须把「进度」这个概念处理干净。最开始我让规划器自己记状态，结果同一轮里被调用两次就错乱。后来改成用 `len(ctx.observations)` 判断进度，规划器变成**无状态**的，问题就消失了。这件事让我理解了一句话：**能在数据结构里表达的，就别放在对象状态里。**

另一个坑是 `PlanContext` 里那个 `observations` 列表。我在测试里把 `ctx` 存起来事后检查，断言一直失败——因为它是同一个列表对象，主循环会继续往里追加，事后再读到的已经不是当初的样子。后来改成当场快照长度，才测出真实行为。这个 bug 让我第一次意识到「测试本身也会骗人」。

## 吴俊达 · 工具实现（数据与安全）

**《那个不报错但也不生效的开关》**

我负责计算器、天气、待办、文件和沙箱这几块，都属于「拿数据 → 返回文本」的工具。踩得最深的不是功能，而是一个**完全静默的配置 bug**。

命令行加了 `--no-network` 之后，我修改的是 `build_agent` 里的局部 `settings` 对象，但工具那边读的是 `get_settings()` 这个全局单例——**两个不同的对象**。代码不报错，只是不生效。发现它是因为演示时我明明断网了，天气却还在返回真实数据，差点以为是缓存。

修的时候又撞上第二个问题：MCP 服务端是**子进程**，它拿不到父进程的 Python 对象。所以离线开关只能通过环境变量传。最后统一成一个 `use_settings()`：更新单例 + 写 `AGENT_OFFLINE` 环境变量，两条路都通。

安全这块也有个教训。我给文件沙箱写了符号链接逃逸的测试，跑了很久一直"通过"。后来才发现 Windows 上没有开发者权限时 `Path.symlink_to()` **既不报错、也没真的建立链接**，等于测试在测空气。加上 `if not link.is_symlink(): pytest.skip()` 之后才诚实——**一个假通过的测试比没有测试更危险**，因为它让你误以为这块已经被守住了。

还有个细节：中文数字只能在**后面跟着量词**时才转换。「三天」→「3天」是对的，但如果不加限制，「算一下」会被改成「算1下」。这种"看起来无害的归一化"能悄悄毁掉整句话的语义。

## 林炳辉 · MCP 协议与集成测试

**《文档说的和 pip 装的不一样》**

我负责 MCP 部分。查了一堆中文教程，写法都是：

```python
from mcp.server.fastmcp import FastMCP
```

照着写完，`pip install mcp` 之后运行：

```
ModuleNotFoundError: No module named 'mcp.server.fastmcp'
```

查了才知道现在装的是 **2.3.0**，v2 把 `FastMCP` 改名成 `MCPServer`，而且**旧路径是直接删除、不是弃用**。客户端那边更彻底：v1 的三层 `stdio_client` + `ClientSession` + `initialize()` 被合并成了一个 `Client(StdioServerParameters(...))`。

这件事给我两个教训：**中文教程普遍滞后**，遇到 ImportError 先去看官方 changelog，别怀疑自己；**依赖要锁版本**，我们现在写 `mcp==2.3.0`，因为 2.x 和 1.x 完全不兼容，不锁版本等于把"能不能跑"交给了别人的发布时间。

第二个坑是我自己撞出来的，任何文档里都没有：从服务端拉工具列表后我写了 `for tool in listed:`，报 `'tuple' object has no attribute 'name'`。`ListToolsResult` 是 pydantic 模型，直接迭代得到的是 `(字段名, 值)` 元组，必须写 `listed.tools`。

第三个坑更隐蔽：我让工具返回 `dict`，想用客户端的 `structured_content` 直接拿结构化结果，结果它一直是 `None`。实测发现**只有返回 `str` 才有 `structured_content`**。于是我们把所有工具统一成返回 JSON 字符串——两种通道的结果结构因此完全一致，主循环一行分支都不用写。

最后一个是我最不想承认的：MCP 的 `list_tools` 不会自带中文标题，导致走 MCP 通道时界面显示 `make_meme` 而不是「生成梗图」。这个"能用但难看"的问题藏了两周，直到有人截图才发现。现在契约测试里加了 `title` 断言。

## 张志远 · 规划器与交互界面

**《让没有大模型的智能体听起来不像复读机》**

我负责规划器和界面。最难的问题不是"怎么匹配关键词"，而是**怎么让人相信它真的在理解**。

第一版我写的是 if-else：

```python
if "天气" in text: ...
elif "算" in text: ...
```

跑演示时被问了一句"天气之子好看吗"，它老老实实去查天气了。这暴露了关键词匹配的根本问题：**它没有"不匹配"的能力**。

后来改成五路加权打分，其中两路是关键的：**负分**（`("天气之子", -8.0)`，专门表达"虽然字面像，但不是"）和**上下文延续**（上一步查了天气、这一步说"画图"，给 +2.0——这是"然后画成柱状图"能命中的唯一原因）。

我还做了 `--debug`，把每一分怎么来的打出来：

```
get_weather: 5.23 (trigger=+3.63, object=+1.00, diversity=+0.60)
make_ascii_art: 0.80 (object=+0.80)
```

这个输出救了我很多次。准确率卡在 92% 时看不出哪里错，打明细才发现"帮我决定吧"被打分器处理时，`帮我` 被当成礼貌用语剥掉了，剩下的"决定吧"匹配不上任何触发词。

界面上我犯过一个低级错误：把图片转 ASCII 预览时用了"越亮越密"的梯度，结果白底图表在终端里糊成一整块 `@@@@`。加了一行判断平均亮度、浅底就翻转梯度才正常。**能自己先看一眼输出的人，不会把这种东西交出去。**

## 黄国轩 · 可视化、图像生成与文档

**《字体文件存在，不代表能显示中文》**

我负责图表、梗图、ASCII 艺术和字体探测，外加全部的文档与博文排版。

中文图表这个需求看着最简单，实际花了我最多时间。第一版我只判断字体文件是否存在：

```python
if Path("C:/Windows/Fonts/msyh.ttc").exists():
    font = ImageFont.truetype("C:/Windows/Fonts/msyh.ttc", 32)
```

在本机跑得好好的。换到一台精简过的机器上，标题全变成了方块 `□□□`。原因是字体文件可能在，但对应字形缺了；`.ttc` 还是字体集合，索引传错也可能取到没有汉字的那个。

改成**真的渲染一次看结果**：

```python
canvas = Image.new("L", (56, 56), 0)
ImageDraw.Draw(canvas).text((6, 6), "测", font=font, fill=255)
if canvas.getbbox() is None:
    continue      # 这个字体画不出汉字，换下一个
```

第二个体会是**该删就删**。我花了不少时间给小恐龙加背刺：先画背刺再画身体，被身体盖住；挪到头顶被头盖住；挪到肩膀，看起来像两只绿耳朵，还和黄色犄角打架。折腾三次之后我把它删了，画面反而干净了——**有些东西加不上就是不该加。**

最后是文档。写博文时我反复问自己："读者凭什么相信 `via=mcp` 不是我们编的？"最后决定把验证方法也写进去：`tasklist` 看子进程、`/trace` 看 `channel` 字段。**能被别人验证的说法，才有说服力。** 也是因为这个，我们把演示素材改成用 `scripts/demo.py` 自动生成，而不是手写截图和数据——手写的会过期，生成的不会。
