## 协作方式

| 环节 | 做法 |
|---|---|
| 需求与设计 | 全组一起定「八个工具 + 两种规划器 + 两条通道」的骨架，再按模块分头实现 |
| 接口约定 | 先定 `ToolSpec` / `ToolResult` / `PlanDecision` 三个数据结构，各模块只依赖这三样，所以可以并行开发 |
| 代码合并 | 由成员 A 统一 review 并提交，保证每次提交都能跑、`pytest` 全绿 |
| 测试归属 | 每个模块的实现者写自己的单测；集成测试（MCP 端到端、网页）由成员 C 负责 |
| 文档 | 成员 D 汇总，各模块负责人提供自己那部分的「踩坑记录」（见 `成员心得.md`） |
